# UX/UI Design

## Purpose
Create calm, accessible, polished product experiences with clear hierarchy and consistent interaction.

## When to use
Use this skill when a project needs ux/ui design as a defined workstream. Combine it with `project-orchestration` for multi-discipline tasks.

## Workflow
1. Identify primary user task, context, frequency, risk, and accessibility needs.
2. Define information architecture and navigation before visual polish.
3. Use a restrained palette: Mors light cyan/sky blue, white, neutral surfaces, high-contrast text; avoid noisy gradients and decorative glass effects by default.
4. Specify states: loading, empty, error, success, disabled, offline, permission denied.
5. Design responsive layouts, keyboard focus, readable type, touch targets, and reduced-motion behavior.
6. Use tokens and reusable components; validate with realistic content and task flows.

## Deliverables
Produce fit-for-purpose artifacts such as: design-brief.md, design-tokens.md, interaction-spec.md. Do not create paperwork that does not help a decision or implementation.

## Quality gates
- Deliverables are specific to the project, internally consistent, and actionable.
- Assumptions and unknowns are explicitly labeled.
- High-impact risks have mitigations or an owner and acceptance decision.
- Claims are supported by implementation evidence or clearly marked as proposals.
- Review for accessibility, privacy, security, maintainability, and user impact as applicable.

## Safety and integrity
Aesthetic choices must support comprehension, not compete with it.
- Ask for clarification only when a missing detail blocks safe or correct work; otherwise state a reasonable assumption.
- Do not expose credentials, personal data, or confidential material in artifacts.
- Do not fabricate external research, test runs, approvals, deployment, or tool outcomes.
- Human approval is required for consequential external actions, production changes, and irreversible operations.

## Handoff
Summarize: objective, decisions, changed/produced artifacts, validation performed, unresolved issues, and next recommended step. Link to artifacts by repository-relative path.
